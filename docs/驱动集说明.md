## 3. FUNB 的真实形态（关键发现）

```
FUNB/AMD/1/

  Drv.reg                    35,604 B     ← UTF-16LE .reg
  Drv.pesrs                  33,894 B     ← 同一内容，hive 前缀不同
```

**FUNB 下 `find . -iname '*.inf' -o -iname '*.cat'` 结果为空。** 整个 FUNB 只有
`sys` / `reg` / `pesrs` 三种文件。

### `Drv.reg` / `Drv.pesrs` 是同一份内容

```
Drv.reg    [HKEY_LOCAL_MACHINE\SYSTEM\ControlSet001\Control\CriticalDeviceDatabase\PCI#VEN_1002&DEV_4380&SUBSYS_280A103C]
Drv.pesrs  [HKEY_USERS\DCSRS\ControlSet001\Control\CriticalDeviceDatabase\PCI#VEN_1002&DEV_4380&SUBSYS_280A103C]
```

两者都是 285 行，去掉 hive 前缀后逐字节相同。

- `Drv.reg` 面向**当前系统**（`HKLM\SYSTEM`）
- `Drv.pesrs` 面向**离线挂载的目标系统**（`HK_USERS\DCSRS`）

`DCSRS` 是 SC 自己起的挂载点名字（`D`=驱动 `C`=CriticalDeviceDatabase `SRS`）。

每个条目的内容：

```ini
"ClassGUID"="{4D36E97B-E325-11CE-BFC1-08002BE10318}"   ; 存储控制器类
"Service"="ahci8086"                                    ; 指向 Services 里的服务名
```

### 对 M6 的影响

要用这批驱动，`--inject-drivers` 必须实现**离线注册表注入**：

```
1. RegLoadKey  挂载 <目标>\Windows\System32\config\SYSTEM 到临时键
2. 复制 <name>.sys → <目标>\Windows\System32\drivers\
3. RegSetValueEx 写 ControlSet00x\Services\<name>
     Type=1(Kernel Driver) / Start=0(Boot) 或 1(System) / ImagePath
4. RegSetValueEx 写 ControlSet00x\Control\CriticalDeviceDatabase\<硬件ID>
     ClassGUID + Service
5. RegUnLoadKey 卸载
```

DISM 只在 `vmd/` 那类**标准驱动包**上还有用武之地。所以 M6 是**两种注入模式**：

| 模式 | 输入形态 | 实现 |
|---|---|---|
| A 标准驱动包 | `.inf` + `.sys` + `.cat` | `dism /image: /add-driver: /recurse` |
| B SRS 注册表绑定 | 裸 `.sys` + `Drv.reg` / `Drv.pesrs` | 离线 hive 注入（上面五步） |

## 5. 版权风险评估

**事实**：这 93 个文件里**没有一个属于 SC**。SC 自己也没取得再分发权 —— 它只是把
厂商和微软随 Windows 分发的成品收集起来打了个口令 7z。这在装机行业是普遍做法
（驱动总裁、万能驱动、SkyIAR 都这么做），行业里普遍无视其法律后果。

**风险评估**：

| 因素 | 判断 |
|---|---|
| 文件年代 | 绝大部分是 2005–2010 年的 XP/7 时代驱动 |
| 厂商维权意愿 | 对十几年前的 IDE/AHCI 驱动基本不追究（对比：对当代显卡驱动会发 takedown） |
| 体量 | 12.7 MB，不显眼 |
| 最坏情况 | 收到 DMCA takedown → 仓库被下线 |

**缓解措施（已写进 `README.md`）**：

1. 独立仓库，**不放进 GPL-3.0 主仓库** —— 一旦被 takedown，主项目不受牵连；
   主仓库 GPL-3.0 里混非 GPL 二进制也会把许可讲不清楚
2. README 明确写"本仓库不主张任何权利""版权归各权利人""收到通知立即删除"
3. `manifest.json` 带 SHA-256，证明文件未经修改
4. `LICENSE` 只覆盖原创文本，明确不覆盖驱动文件

**替代方案（如果不想承担风险）**：仓库只放 `manifest.json` + 一个
`tools/import_drivers.ps1`，用户自己在本地跑一次把驱动导入到指定目录；二进制不入库。
这样拿到的效果一样，风险为零，代价是新用户要自己准备驱动。

## 8. M6 怎么用这批驱动

| 模式 | 输入 | 实现 |
|---|---|---|
| A 标准驱动包 | `vmd/` 下的 `.inf` + `.sys` + `.cat` | `dism /image:<挂载点> /add-driver:<inf> /recurse` |
| B SRS 注册表绑定 | `srs/` 下的裸 `.sys` + `Drv.reg` / `Drv.pesrs` | 离线 hive 注入（`RegLoadKey` → 复制 sys → 写 `Services` → 写 `CriticalDeviceDatabase` → `RegUnLoadKey`） |

`OpenSysprepTool` 的 `--srs <dir>` 指向本仓库的 `srs/`，`--driver <dir>` 指向 `vmd/`。
