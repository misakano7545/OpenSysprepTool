# 开源封装 / 部署项目调研

> 目的：给 OpenSysprepTool 找**可借鉴的实现、检查项与命令行**，不是找可直接链接的库。
> 核对时间：2026-10-26。下面每个仓库都用 `git clone --depth 1` 取到本地，至少读了
> README 与目录结构；低价值条目没有逐文件读源码。HEAD 与提交日期见表。

## 0. 结论

1. **没有可直接对标 SC / EasySysprep 的开源一体化工具。** 最接近的组合是
   `SysprepPreparator`（封装前检查 + 准备任务）+ `DISMTools`（镜像维护）+
   `OSD` / `IronDeploy`（部署端）。
2. 这些项目对本案的价值主要在**行为、检查项、命令行、注册表路径**，不在代码：
   实现语言是 VB.NET / C# / PowerShell，直接搬进 C++ 不现实，也不符合本仓
   「自己写实现」的做法。
3. **许可分层**：
   - GPL-3.0：`SysprepPreparator`、`DISMTools`、`OSD`、`module_system_SysPrep`、`WimWizard`。
     与本项目兼容；但跨语言移植仍是演绎作品，建议按行为重写，复制数据表时登记来源。
   - MIT / Apache-2.0：`unattend-generator`、`toast`、`mysysprep`、`WindowsBuilder`、
     `MDT-Zero-Touch`、`windows-image-factory`、`IronDeploy`。可复用，保留版权声明。
   - **无 LICENSE**：`HDT`、`tiny11builder`、`proactivelabs/packer-windows`、
     `mfgjwaterman/Packer`、`rgl/windows-sysprep-playground`。只读思路，不抄代码或数据表。
4. 核对中发现 Duck.ai 清单有两处不准确：
   - `WIMWitch-tNG` 在 GitHub 上**不存在**（搜索无结果；最接近的是
     `alaurie/WimWitchFK`，MIT，WIM Witch 的社区清理版）。
   - `wataru-super/mysysprep` 已**改名**为 `wataru-c/mysysprep`（MIT）。
5. 顺带发现一个**本仓现有实现的真问题**：`core/unattend` 的 `AutoLogon`
   只写 `Enabled` / `LogonCount` / `Username`，**不写 `Password`**。
   `toast` 的上游实测结论是：Winlogon 会**静默忽略**密码为空的 `<AutoLogon>`，
   空密码账号必须改用注册表 `AutoAdminLogon` + `DefaultPassword`（空 `REG_SZ` 也要存在）。
   我们的 `sysprep.autoLogon` 很可能一直没有生效，需要在 M10 前后修掉。

## 2. 可借鉴点（按本仓模块）

### 2.1 `core/sysinfo` —— 体检项

`SysprepPreparator` 把检查做成 7 个 **CCP**（Compatibility Checker Provider），
每个返回 `Compatible` + `Severity`（Info / Warning / Critical）+ `Resolution`。
这比我们现在的「布尔 + note」更有用：**严重级别和修复建议本身就是产物**。

可直接补进 `--checkup --json` 的检查：

| 检查 | 证据 / 做法 | 严重级别 | 来源 |
|---|---|---|---|
| 待处理服务操作 | `%WINDIR%\WinSxS\pending.xml` 存在；`HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Component Based Servicing\RebootPending` 存在；`...\WindowsUpdate\Auto Update\RebootRequired` 存在 | Critical（阻断封装） | `SysprepPreparator/PendingServicingOperationsCCP.vb`、`toast` |
| 待重命名文件 | `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\PendingFileRenameOperations` 非空 | Info（**不阻断**） | 同上；`toast` 明确说它「在大量健康机器上存在，sysprep 不会因此失败」 |
| BitLocker | `Win32_EncryptableVolume`（`root\cimv2\security\microsoftvolumeencryption`）或 `manage-bde -status`；必须是 **Fully Decrypted**，挂起不够 | Critical（加密卷上 sysprep 可能让数据不可恢复） | `SysprepPreparator/BitLockerCCP.vb`、`module_system_SysPrep`、`toast` |
| 会阻塞 generalize 的 AppX | 已安装给某用户、但未 provision 给所有用户 → `0x80073cf2`。`toast` 的三重排除：`SignatureKind = System`、`IsFramework`、`NonRemovable` | Critical（阻断） | `toast/windows/Prepare-Sysprep-USB.ps1` 的 `Get-SysprepBlockingAppx` |
| 第三方驱动 | `dism /online /get-drivers /format:csv`，筛 `Inbox=False`；或 DISM API 的 `GetDrivers(session, False)` | Warning（提示将随镜像带走） | `SysprepPreparator/DismThirdPartyDriverCCP.vb` |
| 域加入 | `Win32_ComputerSystem.PartOfDomain`；generalize 会破坏域信任 | Warning | `toast` |
| 就地升级痕迹 | `HKLM\SYSTEM\Setup\Source OS*` 子键、`C:\Windows.old` | Warning | `toast` |
| 系统卷脏位 | `chkntfs C:` 或 `fsutil dirty query C:` | Warning（建议先 chkdsk） | `module_system_SysPrep` |
| 无人值守残留 | `C:\Windows\Panther\unattend.xml`、`C:\unattend.xml`、`C:\Windows\System32\Sysprep\unattend.xml` | Warning（会被下次 Setup 重跑） | 本仓已有 Panther 检查；`windows-image-factory` 记录了「answer file 存活到 Panther 并重跑」的故障 |

**AppX 检测的落地方式要选清楚。** `Get-AppxPackage -AllUsers` 是 PowerShell；
C++ 侧要么：

- 走注册表：`HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\AppModel\PackageRepository\Packages`
  + 每用户 `HKCU\...\AppModel\Repository\Packages` + `HKLM\...\Appx\AppxAllUserStore\Applications`，
  做启发式判断；或
- 调 `dism /online /get-provisionedappxpackages` + 注册表，拿「已安装 / 已 provision」两份清单；或
- 只做**只读提示**，把「精确判定」留给 `--prepare` 的修复动作。

`SysprepPreparator` 走的是更简单的 `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\AppModel\StagingInfo`
子键；它对 LTSC 还加了「Store 不在 StagingInfo、但用户 SID 有 `.pckgdep`」的特例。
这条可以作为兜底，但不要当成完整判据。

**严重级别的落点**：`core/sysinfo::CheckupReport` 现在只有 `warnings`；
建议加一个 `checks[]`（`id` / `severity` / `message` / `resolution` / `evidence`），
`--checkup` 的人类可读输出按 severity 排序。这样 `--sysprep` 可以直接消费
`severity == critical` 的项作为 `blockers`，不用再各写一套。

### 2.2 `core/prepare` —— 封装前清理动作

`SysprepPreparator` 的 11 个 **PT** 基本就是 SC「封装前清理」的开源对照。
下面这些都能映射成现有 `prepare::Action`，其中大部分是 `runCommand` + `irreversible`：

| 动作 | 命令 / 路径 | 可回滚 | 备注 |
|---|---|---|---|
| 停止已运行的 sysprep | `taskkill /F /IM sysprep.exe /T` | 否 | 不先停会报「sysprep 已在运行」；`SysprepStopperPT` |
| 清 Windows Update 缓存 | `net stop wuauserv`、`net stop BITS`、删 `%WINDIR%\SoftwareDistribution\Download`、`bitsadmin /reset /allusers`、再启动服务 | 否 | `WindowsUpdateTempFileCleanupPT`；服务原本没跑就不要启动 |
| DISM 组件清理 | `dism /online /cleanup-image /startcomponentcleanup /resetbase` | 否 | **`/resetbase` 让已装更新不可卸载**；Win7 的 DISM 没有这两个开关，Win7 用 `/spsuperseded`，要按 OS 版本分支 |
| 删卷影 / 还原点 | `vssadmin delete shadows /all /quiet` | 否 | `VssAdminShadowVolumeDeletePT` |
| 清事件日志 | `wevtutil el` + `wevtutil cl "<log>"` | 否 | 也可用 `EvtClearLog`（Vista+）；`EventLogPT` |
| 清回收站 | 每个就绪盘符下的 `$Recycle.Bin\<当前用户 SID>` | 否 | `RecycleBinCleanupPT`；要先取 token SID |
| 清「运行」历史 | 删 `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\RunMRU` 的值 | 是（journal） | `UserProfilePT` |
| 清地址栏输入历史 | 删 `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\TypedPaths` 的值 | 是（journal） | 同上 |
| 按关键字清计划任务 | `schtasks /query /fo csv /nh` 后按关键字删 | 否 | `module_system_SysPrep` 默认清 OneDrive 相关；关键字要可配置 |
| 磁盘清理 | `cleanmgr /sagerun:1` | 否 | 依赖预先写好的 `StateFlags`（`HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\VolumeCaches\<handler>\StateFlags0001`）；直接跑很可能什么都不清，**不要假装它能清** |
| 清 unattend 残留 | 删 `C:\Windows\Panther\unattend.xml`、`C:\unattend.xml`、`C:\Windows\System32\Sysprep\unattend.xml` | 否 | 封装前必须确认用哪一份；`module_system_SysPrep` 的 `UNATTEND_CLEAN` |
| 导出存储/网卡驱动 | 按 `DismDriverPackage.ClassName in {SCSIAdapter, Net}` 复制 `OriginalFileName` 所在目录 | 是（复制） | `EssentialDriverExportPT`；为换硬件部署留驱动，不是注入 |

**不建议照搬的动作**：

- `module_system_SysPrep` 的「启用 Administrator + 空密码」。这会把目标机变成无密码管理员，
  与「去流氓」不冲突但属于**降低安全性**；本仓已有 `deploy.enableAdministrator`，
  密码应通过 unattend 的 `LocalAccount/Password` 或首次登录设置，不设空密码。
- `ExplorerStopperPT` 的 `taskkill /f /im explorer.exe`。封装前杀 explorer 会让当前会话
  黑屏；除非后续马上 sysprep/shutdown，否则不该做。可以作为「sysprep 前一刻」的步骤，
  不要放进常规 prepare 列表。
- `cleanmgr /sagerun:1` 的「看起来做了」。如果 StateFlags 没配，它静默什么都不做；
  要么显式写 StateFlags，要么不提供这个开关。

### 2.3 `core/sysprep` —— 编排与阻塞项

`SysprepPreparator` 的 `SetupStateCCP` 把 `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Setup\State\ImageState`
映射成 7 个状态。它的「好状态」是 `*_RESEAL_TO_AUDIT`，因为它的工作流是 **Audit Mode 里准备**；
我们的工作流是「正常装好的系统 → generalize」，好状态应是 `IMAGE_STATE_COMPLETE`。
**不要把它的状态机照抄**，只借它的状态枚举与「非预期状态要给出 Resolution」的做法。

值得补进 `sysprep::Report::blockers` 的：

- `pending.xml` / CBS `RebootPending` / WU `RebootRequired` → 阻断；
- BitLocker 未完全解密 → 阻断；
- 会阻塞 generalize 的 AppX → 阻断；
- 系统卷脏位 → 阻断（先 chkdsk）；
- 域加入 → 只警告（generalize 后需要重新加域）；
- `PendingFileRenameOperations` → 只记录，不阻断（`toast` 的实测结论）。

调用序列本身各家一致：

```
taskkill /F /IM sysprep.exe /T
sysprep.exe /generalize /oobe /shutdown /quiet /unattend:<path>
```

`toast` 把 unattend 放在 `C:\Windows\System32\Sysprep\unattend.xml` 再传 `/unattend:`；
`Packer` 模板还常用 `/mode:vm`（VM 模板，跳过部分硬件检测）。我们的
`sysprep::Options::mode` 目前是 `classic / antiRogue / volume`，如果要做 VM 模板，
可以再评估 `vm`，但不要和 SC 的「防流氓」模式混在一起。

**AutoLogon 的真问题**（见 §0 第 5 条）：`toast` 的注释说得很具体——

> Winlogon silently IGNORES an unattend `<AutoLogon>` block whose password is blank
> (confirmed on a customer unit 2026-07-14) -- for blank-password accounts, autologon
> must be set via registry instead, and `DefaultPassword` must EXIST as an empty
> `REG_SZ` or `AutoAdminLogon` is ignored too.

我们现在的产物没有 `<Password>`，所以：

- 账号有密码 → 不会自动登录；
- 账号空密码 → 按 `toast` 的实测，也不会自动登录。

修法二选一：

1. 配置模型加 `autoLogonPassword`，按 unattend 规范编码
   `Base64(UTF-16LE(password + "Password"))` 写 `<Password>`；
2. 空密码时改走 `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon`
   的 `AutoAdminLogon=1` / `DefaultUserName` / `DefaultPassword=""`（空 `REG_SZ` 必须存在），
   并可用 `AutoLogonCount=1` 限制首次启动。

### 2.4 `core/dism` —— 镜像操作与错误处理

`DISMTools` 的 `ProgressPanel.vb` 把 DISM 操作编成 40+ 个 `opNum`
（Capture / Apply / Mount / Unmount / Export / Split / FFU / Packages / Features /
Capabilities / Drivers / Apply-Unattend / ISO …）。这是一份很好的**未来 CLI 子命令清单**，
但它的实现走 `DismApi`，与宪章 §1「只用命令行」冲突——**只借目录，不借调用方式**。

它还有一份 `Elements/AutoUnattend/Component.xml`：84 个组件 ID + 支持的 pass
（`offlineServicing` / `windowsPE` / `generalize` / `specialize` / `auditSystem` /
`auditUser` / `oobeSystem`）。可以拿来做 `--gen-unattend` 的**组件/pass 合法性校验**，
但这份表的来源没有标注，权威口径仍是 ADK 的 `Unattend.chm`；不要把它当唯一真相。

我们现在的 `dism::runCommand` 只取退出码，不读 stdout/stderr。`DISMTools` 与
`IronDeploy` 都会把输出逐行记日志，并在失败时保留最后 N 行。建议：

- `runCommand` 增加可选的 `captureOutput`，失败时把最后 8–10 行写进错误信息；
- DISM 的 `0x800f081f` 之类 HRESULT 要原样打印，不要只报「exit code 1」；
- 长时间操作（`/StartComponentCleanup`、`/Apply-Image`）要有进度回调或至少心跳日志。

### 2.5 部署 / 捕获（未来里程碑，不在 M10）

`IronDeploy` 的 WinPE 序列是目前看到最完整、最接近 SC/ES「部署到新机」的开源实现：

```
diskpart /s diskpart-uefi.txt
  select disk N / clean / convert gpt
  create partition efi size=300 / format quick fs=fat32 label="System" / assign letter=S
  create partition msr size=16
  create partition primary / format quick fs=ntfs label="Windows" / assign letter=C
dism /Apply-Image /ImageFile:... /Index:N /ApplyDir:C:\
dism /Image:C:\ /Add-Driver /Driver:<pkg> /Recurse
dism /Image:C:\ /Apply-Unattend:<file>
bcdboot C:\Windows /s S: /f UEFI
```

两个安全细节值得直接借：

1. **破坏性命令前重新核验目标盘**：`IronDeploy` 在 `clean` 前重新读
   `Number` / `Model` / `SizeBytes`，与用户确认时不一致就中止。盘序号会变，
   「第一块盘」在双盘机上就是数据事故。
2. **diskpart 失败要带最后几行输出**：只报 exit code 无法定位是哪一行分区命令失败。

`OSD` 的 `New-OSDisk` 给的是另一套默认布局：EFI **260 MB**、MSR **16 MB**、
Recovery **990 MB**、其余给 Windows；MBR 下系统分区也是 260 MB。
`IronDeploy` 用 EFI 300 MB、MSR 16 MB、**不建 Recovery**。两者都能工作，
差别在恢复分区与 Windows RE；如果我们要做「部署到裸机」，需要先定一套布局并写进宪章，
不要在不同机器上漂移。

`toast` 的价值在**捕获前的判断**，不在 Clonezilla 本身：

- BitLocker 必须**完全解密**，不是挂起；加密卷上 sysprep 可能让数据不可恢复；
- 捕获前按「已用空间」估算目标 U 盘容量，不能按分区总大小；
- Clonezilla/partclone 按原文件系统偏移写回，**要恢复到更小的盘必须在捕获前收缩**，
  恢复时加参数来不及；这是 `toast` 整篇 README 的核心教训；
- 目标盘按**身份**（型号/序列/大小）解析，不按「第一块盘」。

如果我们只做 DISM/WIM 路线，partclone 的偏移问题不存在；但只要引入
「整盘克隆 / Clonezilla」路线，这三条就必须一起考虑。

`windows-image-factory` 的 `docs/gotchas.md` 是另一份高价值材料（MIT），
对无人值守安装/部署直接相关：

- XML 注释里出现 `--` 会让 answer file 解析失败，Win11 24H2 / Server 2025
  的表现是**无限重启且零写入**，没有任何错误提示；
- Server 2025 的 SAN 策略会让虚拟盘保持 offline，`<DiskConfiguration>` 静默不生效；
  需要在 `windowsPE` pass 先跑 `diskpart` 的 `san policy=onlineall`；
- WinPE 缺存储驱动时，用启动介质根目录的 `$WinpeDriver$`，不要用
  `<DriverPaths>`（它要盘符，而 WinPE 盘符按枚举顺序变）；
- 判断「安装是否真的开始」看**写入量**，不要看屏幕；读 ISO 600 MB 后停住
  通常是在等对话框，读个不停且零写入通常是 answer file 解析失败的重启循环。

这些应该进我们的**集成测试/排错手册**，不一定进产品代码。

## 3. 不能 / 不建议借鉴

| 项 | 原因 |
|---|---|
| `DISMTools` 的 `DismApi` 进程内调用 | 与宪章 §1 冲突；继续 `CreateProcess` 调 `dism.exe` |
| `SysprepPreparator` 的 VB 代码逐行移植 | GPL-3.0 兼容，但跨语言移植是演绎作品；按行为重写更干净 |
| `module_system_SysPrep` 的「空密码 Administrator」 | 降低目标机安全性；密码应可配置，不默认空 |
| `cleanmgr /sagerun:1` 直接当清理动作 | 没配 `StateFlags` 时静默什么都不做 |
| `tiny11builder` / `HDT` / 三个 Packer 模板的代码 | 无 LICENSE，默认保留所有权利；只读思路 |
| SC / ES 的主页、扩展、推广、联盟、防卸载驱动 | 宪章 §7 红线，任何参考项目里出现也不跟 |
| 任何「检测/规避安全软件」的写法 | 同上 |

## 4. 建议落地顺序

按「能独立验收、改动面小、直接补现有缺口」排序：

### M10a — 体检阻塞项（只读，先做）

- `core/sysinfo` 增加：pending servicing、BitLocker、AppX 阻塞项、脏位、域加入、
  就地升级痕迹、第三方驱动计数；
- `CheckupReport` 增加 `checks[]`（id / severity / message / resolution / evidence），
  保留现有字段不破坏 `verify_checkup.py`；
- `core/sysprep` 把 `severity == critical` 的项接进 `blockers`；
- 验收：新增 fixture 覆盖「有 pending.xml」「BitLocker 未解密」「PFRO 非空」三类，
  断言严重级别与 `--sysprep` 的阻断行为；负例证明 PFRO **不**阻断。

### M10b — 封装前清理动作（可预览、可回滚的尽量回滚）

- `core/prepare` 增加：WU 缓存、DISM 组件清理（按 OS 版本分支）、卷影、事件日志、
  回收站、RunMRU/TypedPaths、计划任务、sysprep 残留进程、unattend 残留；
- 每个动作在 `--prepare --dry-run` 打印**完整命令行**与「不可回滚」标记；
- 验收：`verify_prepare.py` 增加动作计数与命令文本断言；不可回滚动作不得写 journal。

### M10c — AutoLogon 修正（配置模型小改）

- 加 `autoLogonPassword`（可选）或空密码注册表回退；
- `--gen-unattend` 产物断言 `<Password>` 存在且编码正确（用已知向量）；
- 验收：`verify_unattend.py` 增加「有密码 / 空密码」两组合法性断言。

### M11 — 部署到裸机（需要宪章新增里程碑）

- 磁盘布局（EFI/MSR/Recovery 尺寸）先定死；
- diskpart → DISM apply → driver → unattend → bcdboot；
- 目标盘二次核验、失败保留 diskpart 尾部输出、不可回滚步骤逐条标注；
- 这是**新功能**，不要塞进 M10。

离线 WIM 维护（`WimWizard` 那条线）是另一个产品形态：它处理安装镜像，
不是「已装好的系统 → sysprep → 捕获」。如果以后要做，单独开里程碑，
不要和在线封装混在一起。
